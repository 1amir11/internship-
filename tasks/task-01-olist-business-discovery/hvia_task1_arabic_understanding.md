# أ) بحث الشركة — Olist عبر الزمن

## لمحة سريعة

| البند | التفاصيل |
|--------|----------|
| الاسم القانوني | Olist Serviços Digitais Ltda. |
| التأسيس | 2014 (نشاط تجاري من 2015) |
| المؤسس والرئيس | Tiago Dalvi |
| المقر | كوريتيبا، البرازيل |
| حجم الفريق | ~790–850 |
| التقييم | يونيكورن $1.5B (ديسمبر 2021) |
| التمويل | أكثر من $320M |
| التجار | 50,000+ |
| العميل الأساسي | تجار SMB / علامات؛ المستهلك النهائي ظاهر في طلبات الداتا |

**الفكرة:** Olist بتساعد التجار الصغار يبيعوا أكتر عبر التكنولوجيا.

## إيه اللي يهمنا في التاسك؟

الداتا العامة = طلبات **2016–2018** تحت موديل **Marketplace Aggregator / Olist Store**:
- تاجر صغير ينضم لـ Olist
- المنتج يتباع تحت واجهة/حساب **Olist** الموحّد على الماركت بليس
- العميل يشتري من «Olist»
- التاجر يشحن
- الإيراد وقتها: عمولة تقريبًا **19–21%** + رسوم

**مخاطر الموديل ده:**
1. هوامش وسيط ضعيفة  
2. **عدوى السمعة** على الحساب الموحّد (بائع سيء يضر الكل)  
3. خروج التجار لما يكبروا ويقدروا يفتحوا حساب مباشر  

لاحقًا (بعد الداتا): تحولت لـ Commerce OS — Tiny ERP، Vnda، Pax، Flip، PDV، Lis.  
ده سياق بحث الشركة فقط — **مش** بنفرض منتجات 2025–2026 على كل رقم في التحليل.

## تايملاين مختصر (إيه اتضاف امتى)

# ب) فهم الداتا

## إيه الداتا؟
- استخراج عام لطلبات التجارة الإلكترونية البرازيلية (Olist Store)
- تقريبًا من **2016-09-04** إلى **2018-10-17**
- ~**99.4 ألف** طلب عبر **9 جداول**
- مش موجودة: ميزانية إعلانات، فواتير اشتراك التجار، منتجات SaaS بعد 2018

## الجداول التسعة

| الجدول | الصفوف تقريبًا | الدور |
|--------|----------------|-------|
| orders | 99,441 | المحور: الحالة + تواريخ الشراء/الموافقة/الشحن/التسليم/ETA |
| order_items | 112,650 | عناصر السلة: منتج، بائع، سعر، شحن (~1.14 عنصر/طلب) |
| customers | 99,441 | الموقع؛ `customer_unique_id` = الشخص الحقيقي (96,096) |
| sellers | 3,095 | موقع البائع |
| products | 32,951 | فئة، صور، وزن/أبعاد |
| payments | 103,886 | نوع الدفع والأقساط |
| reviews | 99,224 | تقييم 1–5 + نص اختياري |
| geolocation | ~1M | إحداثيات — كتير لكل ZIP → نأخذ المتوسط |
| category_translation | 71 | ترجمة الفئة برتغالي → إنجليزي |

## ترتيب الفهم (تسلسلي)
1. ابدأ من **orders** (~97% مسلَّم)  
2. اربط **items → products → sellers** (الإيراد على مستوى العنصر؛ جمّع للطلب)  
3. اربط **customers + payments** (الولاء من `customer_unique_id` فقط)  
4. اربط **reviews + geo** (جمّع التقييم لو فيه تكرار؛ متوسط lat/lng لكل ZIP)

## جودة مهمة
- تواريخ تسليم ناقصة غالبًا لغير المسلَّم  
- نصوص المراجعات ناقصة كثير (~59% بدون رسالة) → تحليل النص عيّنة متحيزة  
- لا تخلط مستوى العنصر مع مستوى الطلب في حساب التأخير vs التقييم  

## لقطة أرقام سريعة
| مؤشر | قيمة |
|------|------|
| إيراد منتجات / AOV | R$13.6M / ~R$138 |
| تأخير عن ETA | 6.8% من 96,470 مسلَّم |
| تقييم في الوقت vs متأخر | 4.29 vs 2.27 |
| مشترٍ مرة واحدة | 96.9% |
| أعلى 10% بائعين → إيراد | ~67.5% |
| نصيب SP (عملاء / بائعين) | ~42% / ~60% |

# ج) التحليل وقصة البيزنس (المشاكل)

**اقرأ كسلسلة سبب:**  
نمو سريع → جغرافيا/مسافة وشحن → تأخير → انهيار التقييم وشكاوى → ولاء ضعيف — مع تركّز بائعين تحت وجه Olist واحد.

## ج.1 نمو سريع وموسمية (ضغط تشغيلي)
- نمو طلبات حاد (مع تحذير early-base في بداية 2017)  
- ذروة نوفمبر 2017: **7,544** طلب (سياق Black Friday)  
- الإلغاء ~1.2% ثانوي  
- **شارت:** `01_monthly_order_volume`

## ج.2 فجوة جغرافية وشحن
- SP يسيطر على العملاء والبائعين  
- نفس الولاية ~7.5 يوم vs بين الولايات ~14.7 (+~7.2)  
- وسيط المسافة ~434 كم؛ ارتباط المسافة بأيام التسليم ~0.39  
- الشحن ~17% من إيراد المنتجات؛ حصة الشحن من (سعر+شحن) ~21%  
- **شارت:** `16_distance_vs_delivery` (+ `11`, `12`, `13`)

## ج.3 التأخير يدمّر التقييم (أقوى مشكلة)
- بس **6.8%** متأخرين عن ETA  
- التقييم: **4.29 → 2.27** (−2.02 نجمة)  
- متوسط فعلي ~12.1 يوم vs تقديري ~23.4 (buffer كبير ومع ذلك الـ late مؤلم)  
- في موديل الحساب الموحّد = **عدوى سمعة** مش بس CX  
- تعليقات 1★: تسليم/تأخير ~41% vs منتج ~13%  
- **شارت:** `06`, `04`, `05`, `18`, `07`

## ج.4 ولاء شبه صفر + Pareto بائعين
- 96.9% يشتروا مرة واحدة؛ 3.1% يرجعوا  
- أعلى 10% بائعين → ~67.5% إيراد؛ أدنى 50% → ~3.2%  
- البائع الضعيف ممكن يضر السمعة زي ما النخبة بتجيب GMV  
- **شارت:** `08`, `10`

## خريطة الأولويات (للحلول)

| ترتيب | المشكلة | ليه تهم البيزنس 2016–18 |
|--------|---------|-------------------------|
| 1 | تأخير → انهيار تقييم | سمعة الحساب الموحّد |
| 2 | انعدام تكرار الشراء | CAC مرة واحدة، LTV ضعيف |
| 3 | تركّز بائعين + ذيل خطر | هشاشة GMV + عدوى سمعة |
| 4 | فجوة جغرافية | وعد تسليم غير متساوٍ |
| 5 | ضغط الشحن | سعر مدرَك + حساسية للتأخير |

## الحل الأساسي 1 — توقع مخاطر التأخير والاستجابة (P1)

**المشكلة:** 6.8% late بس التقييم ينهار 4.29→2.27 — سمعة الحساب الموحّد.

**يعمل إيه؟** وقت ما التاجر بيجهّز الشحن، يحسب احتمال إن الطلب يفوّت الـ ETA الموعود (حتى لو فيه buffer كبير).

**مدخلات:** المسافة، نفس الولاية/بين الولايات، الوزن/الفئة، تاريخ التزام البائع (من حل 3)، ضغط حجم الطلبات (من إشارة الموسمية).

**تصرف حسب الخطر:**
- منخفض: مسار عادي  
- متوسط: إخطار استباقي للعميل بموعد واقعي معدّل **قبل** فوات ETA  
- عالي (+ بائع ضعيف): تصعيد للتاجر للاستعجال + أولوية دعم لو حصل تأخير  

**KPI:** تصغير فجوة التقييم بين on-time والـ late (الأساس −2.02) لمجموعة تم إخطارها vs مجموعة مقارنة.

**دليل:** شارت 04، 05، 06، 15.

---

## الحل الأساسي 2 — علم مخاطر عدم العودة بعد أول طلب (P2)

**المشكلة:** 96.9% مرة واحدة فقط — النمو اكتساب مش ولاء.

**يعمل إيه؟** بعد اكتمال أول طلب (تسليم + تقييم، أو تسليم بدون تقييم بعد N يوم)، يقيّم احتمال إن العميل يرجع — بدل حملة «ارجع» للكل.

**مدخلات:** هل الطلب كان متأخر/عالي الخطر (حل 1)، صحة البائع (حل 3)، قيمة/فئة الطلب، التقييم إن وُجد.

**تصرف:** عملاء عاليي القيمة + عاليي خطر الترك → تواصل خفيف (متابعة دعم أو لفتة صغيرة) بتكلفة متناسبة.

**KPI:** نسبة إعادة الشراء في المجموعة المستهدفة vs خط الأساس 3.1%.

**دليل:** شارت 08.

---

## الحل الأساسي 3 — درجة صحة البائع Seller Health Score (P3)

**المشكلة:** 10% من البائعين ≈ 67.5% إيراد؛ الذيل الطويل يشارك نفس وجه Olist.

**يعمل إيه؟** درجة مركّبة لكل بائع: معدل التأخير، متوسط التقييم، مساهمة الإيراد، اتجاه النمو.  
شرائح مثل: احمِ ونمِّ / راقب / يحتاج تدخل (أي حجم — لو نمط التسليم/التقييم بيهدد الحساب الموحّد).

**تصرف:** الشريحة تدخل كمدخل في حل 1؛ موارد الدعم تتركّز على «يحتاج تدخل» بدل توزيع متساوٍ على 3,095 بائع.

**KPI:** اكتشاف مبكر لبائعي خطر السمعة؛ انخفاض حصة الإيراد من شريحة الخطر مع الوقت.

**دليل:** شارت 10.  
**ملاحظة بناء:** خلّي حل 3 يطلع أول أو مع حل 1 (لأن 1 محتاج الدرجة).

## طبقات داعمة (مش منتجات منفصلة للبيع لوحدها)

### ETA ديناميكي جغرافي (P4 → يغذي حل 1)
بدل ETA وطني مسطّح بـ buffer كبير: تقدير حسب المسار (نفس الولاية / بين الولايات / شرائح المسافة).

### فرز نص المراجعات (P6 → يغذي 1 و 2)
شكاوى التسليم ~41% من تعليقات 1★؛ متوسط الرد ~40 ساعة.  
مصنّف خفيف يوجّه الشكاوى اللوجستية لطابور دعم فوري + يفيد أوزان موديل التأخير.

### إشارة الطلب الموسمي (P7 → يغذي حل 1)
في الذروة (مثل نوفمبر) خطر التأخير يرتفع لوحده — مضاعف خطر في حل 1 وقت المواسم المتوقع ارتفاعها.

### جانبي: تنبيه نسبة الشحن في الكتالوج (P5)
لما منتج يُضاف/يُسعَّر: لو نسبة الشحن للسعر فوق حد → تدخل تسعير/تجميع/ناقل قبل ما التحويل يضعف.
